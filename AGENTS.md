# Storefront conventions
- Keep sourcing promotion in the storefront presentation layer and link to the existing B2B inquiry flow; promotional changes must not alter inquiry or purchase behavior.
- Product and category showcases use live catalog records, never invented merchandise or fallback slide content; the shared ProductCard controls catalog image presentation.
- Bila credentials stay in server-side project secrets; the admin-only readiness endpoint returns configuration presence without contacting the provider, so setup checks cannot charge customers or expose credentials.
- Bila orders use an immutable server-calculated payment snapshot and one claimed collection per order; ambiguous responses are checked by reference rather than resubmitted to prevent duplicate charges.
- Bila payment confirmation and rewards run transactionally through a service-only function after matching the provider's reference, ZMW currency and exact amount; customer order history provides status checks without trusting browser payment state.
